# AI 小学生课外辅导章节测试功能开发需求

我们还需要做一个“章节测试”功能，用来判断学生学完一章后的掌握情况，并把测试结果反哺到 Memory 和后续预习中。

这个功能的核心不是单纯打分，而是形成学习闭环：

学完一章 -> 生成章节测试 -> 学生作答 -> AI 批改和诊断 -> 记录薄弱点/优势点 -> 更新学生 Memory -> 根据学生情况安排复习和下一章预习。

## 一、核心目标

1. 学生学完一个章节后，系统能生成或调用对应章节测试。
2. 测试题要覆盖本章关键知识点，难度适合当前年级。
3. 学生提交答案后，AI 能批改并分析错误原因。
4. 系统能记录学生的薄弱点、常见错误、掌握较好的知识点。
5. 测试结果要更新到学生 Memory。
6. 后续预习时，要结合测试结果调整预习内容和讲解方式。

## 二、第一版要做的 5 件事

### 1. 章节测试生成

学生学完某个章节后，系统根据教材知识库生成一份测试。

测试内容建议包括：

- 本章核心知识点
- 基础题
- 应用题
- 易错题
- 1-2 道综合题，如果适合当前年级

每道题需要标记：

- 年级
- 学科
- 教材版本
- 单元/章节
- 课时
- 知识点
- 难度
- 标准答案
- 解析

第一版可以先做固定题量，例如每章 8-12 题。

### 2. 学生作答和提交

学生完成测试后，系统保存完整作答记录。

每次测试记录建议包含：

- student_id
- test_id
- subject
- grade
- unit
- started_at
- submitted_at
- answers
- time_spent

每道题的作答记录建议包含：

- question_id
- student_answer
- correct_answer
- is_correct
- time_spent
- knowledge_point

### 3. AI 批改和错误诊断

学生提交后，AI 对答案进行批改，并分析错误原因。

诊断时不要只给“对/错”，还要判断：

- 哪个知识点没掌握
- 是概念不懂、计算错误、审题错误，还是步骤不完整
- 是否属于本章常见易错点
- 是否需要回到前置知识复习

错误类型可以先用：

- concept_gap：概念理解不清
- calculation_error：计算错误
- reading_error：审题错误
- method_error：方法选择错误
- careless_error：步骤遗漏或抄写错误
- prerequisite_gap：前置知识不稳

注意：不要直接把学生定义成“粗心”或“不认真”，只能记录具体行为。

### 4. 更新学生 Memory

测试结束后，系统把诊断结果写入学生 Memory。

可以写入的记忆包括：

- 本章掌握较好的知识点
- 本章薄弱知识点
- 常见错误类型
- 需要复习的前置知识
- 适合的讲解方式

示例：

学生在“面积单位换算”连续错 3 题。

可以更新 Memory：

“学生在面积单位换算中对单位进率掌握不稳定，需要通过表格和例题加强。”

不应该写：

“学生单位换算很差。”

### 5. 根据测试结果调整预习

学生进入下一章节预习时，系统要结合测试结果调整预习内容。

例如：

- 如果上一章基础知识掌握不稳，预习前先补 1-2 个前置知识点。
- 如果学生某类题反复错，预习时提前提醒相关易错点。
- 如果学生适合画图理解，预习内容就优先用图示、分步骤讲解。
- 如果学生掌握较好，可以减少重复基础讲解，增加一点应用练习。

也就是说，预习不应该只看教材知识库，还要读取学生 Memory。

## 三、建议的数据结构

### 1. chapter_tests

保存章节测试基本信息：

- test_id
- subject
- grade
- version
- semester
- unit
- lesson_range
- title
- question_ids
- created_at

### 2. test_questions

保存测试题：

- question_id
- test_id
- subject
- grade
- unit
- knowledge_point_id
- difficulty
- question_type
- content
- correct_answer
- explanation
- metadata

### 3. test_attempts

保存学生一次测试记录：

- attempt_id
- test_id
- student_id
- started_at
- submitted_at
- score
- time_spent
- status

### 4. test_answers

保存每道题的作答情况：

- answer_id
- attempt_id
- question_id
- student_answer
- is_correct
- score
- time_spent

- created_at

保存一次测试后的整体诊断：

- subject
- unit
- mastered_points
- weak_points
- error_patterns
- prerequisite_gaps
- review_suggestions
- memory_updates
- created_at

## 四、第一版验收标准

1. 学生学完某章节后，系统能生成或调用一份章节测试。
2. 测试题能关联到教材章节和知识点。
3. 学生提交答案后，系统能保存完整作答记录。
4. AI 能批改答案，并给出错误类型和知识点诊断。
5. 测试结果能更新到学生 Memory。
6. 学生进入下一章节预习时，预习内容会参考上一章节测试结果。
7. 系统不会生成“学生很笨”“学生不认真”这类负面人格标签。
8. 对于没掌握的知识点，系统能给出复习建议。

## 五、和 Memory、教材知识库的关系

章节测试功能需要同时连接两个模块：

1. 教材知识库

用来决定“测什么”。

系统根据教材知识库里的年级、学科、教材版本、单元、课时、知识点来生成测试题。

2. 学生 Memory

用来记录“学生掌握得怎么样”。

测试结束后，把薄弱点、优势点、错误模式、学习方式等写入 Memory。

后续预习时，系统同时读取：

- 教材知识库：下一章要学什么。
- 学生 Memory：这个学生需要先补什么、适合怎么讲。

最终目标是让系统不只是“讲下一章”，而是“根据这个学生的情况讲下一章”。

## 六、测试用例

### 测试 1：章节薄弱点

输入：

学生完成“面积单位”章节测试，其中单位换算题 4 题错 3 题。

期望：

系统更新 Memory：

“学生在面积单位换算中对单位进率掌握不稳定，需要通过表格和例题加强。”

下一次预习：

进入下一章节前，AI 先带学生快速复习面积单位进率。

### 测试 2：错误类型

输入：

学生应用题列式正确，但计算结果错误。

期望：

诊断为 calculation_error，而不是 concept_gap。

系统不要误判为“概念不会”。

### 测试 3：前置知识不稳

输入：

学生做小数相关题目时，反复暴露整数位值理解不清。

期望：

系统记录 prerequisite_gap：

“学生对整数位值概念掌握不稳定，影响后续小数学习。”

下一次预习小数内容时，AI 先补充位值相关知识。

### 测试 4：掌握较好

输入：

学生本章测试大部分题目正确，且综合题也能说明思路。

期望：

系统记录优势：

“学生对本章基础概念掌握较好，可以适当增加应用型练习。”

下一次预习：

减少重复基础讲解，增加一点应用练习。
