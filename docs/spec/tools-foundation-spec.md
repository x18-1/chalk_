# Tools 基础能力 Spec

> 文档状态：Draft
> 适用范围：Chat Agent 的第一阶段 Tools 基础能力
> 分支：`feat/tools-foundation`
> 最后核验：2026-08-24

## 1. 背景

Chalk 当前已经支持内置工具、MCP 工具和 Subagent 工具，但工具执行保护不完整：通用工具没有统一超时和结果预算，用户配置可以覆盖工具声明的审批要求，工具清单与实际装配存在分叉，错误状态主要依赖普通 `Error` 文本。

这些问题会直接影响 Agent run 的可用性：一个慢工具可能长期占用运行；一个超长结果可能堵塞上下文；一个错误的权限设置可能让副作用工具绕过审批；设置页还可能无法反映真实工具面。

## 2. 目标

第一阶段完成一个可用于 Chalk 平台的 Tool 基础执行层：

- 工具能力和副作用可被统一描述；
- 每次调用有明确的超时、取消和结果大小边界；
- 平台强制审批不能被用户偏好绕过；
- 工具失败能够被稳定分类；
- 工具注册和清单在装配阶段可验证；
- 当前工具的实际功能与公开描述一致；
- 核心行为有单元测试和必要的集成测试。

## 3. 非目标

本阶段不实现：

- 参数字段级脱敏；
- 工具 marketplace、安装签名或远程供应链验证；
- 多实例工具执行队列；
- 复杂配额、计费和成本预算；
- 课程图、题库、画像、判题等业务工具；
- Skills 和 MCP 的新能力。

## 4. 用户可见行为

### 4.1 工具设置

设置页显示的工具必须与当前用户下一次 runtime 实际可用的工具一致，并展示：

- 工具名称和用途；
- 来源；
- 是否启用；
- 平台要求的审批状态；
- 用户可调整的审批偏好范围。

如果用户选择了平台不允许的“不询问”，API 必须拒绝保存或将其规范化为平台最低策略，不能只在前端隐藏选项。

### 4.2 工具执行

- 工具在超时前完成则正常返回；
- 工具超时必须终止等待并产生 `timed_out` 状态；
- Agent run 被中止时，工具必须收到取消信号；
- 结果超过模型预算时必须被截断并带有结构化标记；
- 审批拒绝、审批超时、取消、执行超时和工具执行失败必须通过稳定错误码对 UI/telemetry 可区分；
- 没有审批能力时，要求审批的工具不得执行。

结果超过预算时只返回有限文本和 `details.resultTruncated`。第一阶段不声称所有工具都支持继续读取；只有显式定义 cursor/token 的分页工具才能继续读取，通用 continuation 约定列入后续阶段。

### 4.3 当前内置工具

- 学习资源搜索只有在注入真实 `SearchProvider` 时才可用；没有真实 Provider 时不能向学生返回伪造的学习资源。
- 会话重命名属于修改用户数据的工具，必须遵守平台强制审批和 conversation owner 校验。
- `run_subagent` 第一阶段作为内部能力保留：主 runtime 可装配但 `defaultEnabled: false`，不进入公开 `/tools` 设置清单，也不能通过普通用户设置启用。未来对主 Agent 公开时，必须同时进入工具清单和设置页。
- `read_resource` 是 Agent 唯一的公共 Read 工具；第一阶段只注册 `upload` adapter，读取当前会话、当前用户已确认归属的文本上传文件；通过 MinIO/S3 Range 分段读取，并返回签名 continuation cursor。PDF、图片、知识库和 Web 正文通过独立 adapter 接入，不新增 `read_xxx` 工具，也不在本工具中猜测解码方式。
- Read 的 `maxBytes` 为单次 Range 的硬上限；若完整行跨越 Range 边界且本页没有任何可消费的完整行，必须返回 `read_line_too_large`，不得生成 `nextByte` 不变的 continuation cursor。

## 5. 运行时契约

每个 Tool 在注册时声明：稳定名称、用途、来源、副作用、审批底线、超时预算、结果预算和执行模式。ToolRegistry 负责把声明解析成当前用户的有效策略，再生成 Pi `AgentTool`。

执行顺序固定为：定义校验、可见性筛选、参数校验、取消检查、审批、带预算执行、结果归一化、事件和 telemetry。

## 6. 验收标准

### 必须通过

- 注册非法 Tool 会立即失败；
- 重名 Tool 会立即失败；
- 默认超时能终止不返回的 Tool；
- `AbortSignal` 取消后不会继续进入 Tool implementation；
- 文本结果不会超过平台硬上限；
- 工具自身的强制审批不能被 `never` 用户设置关闭；
- 无审批 port 时副作用 Tool 不执行；
- 错误类别不依赖错误 message 文本；
- 真实 SearchProvider 缺失时不注册静态假搜索；
- `/tools` 返回的清单与 Agent 实际注入的公开工具一致；内部 `run_subagent` 在公开设置清单之外并保持默认关闭。

### 暂不作为门禁

- 参数原文是否已字段级脱敏；
- 多进程同时调用时的全局配额；
- 工具版本升级后的旧设置迁移；
- 真实第三方搜索 Provider 的质量。

## 7. 待确认决策

实现前需要最终确认以下产品选择：

1. 是否将当前已实现的 30 秒默认工具超时、120 秒硬上限固化为 Accepted；
2. 是否将当前已实现的 12,000 字符默认结果预算、32,000 字符硬上限固化为 Accepted；
3. 是否将 `write`、`process`、`paid` 的审批底线扩展到所有未来工具；
4. 是否公开 `run_subagent` 并为其建立设置页配置；
5. 是否在下一阶段为分页工具抽象通用 continuation 契约。
