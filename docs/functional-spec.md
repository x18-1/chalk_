# Chalk 产品功能定义

> 状态：草案，随讨论迭代
> 范围：只定义"要做什么功能"，不含技术选型、架构和数据模型

## 1. 产品定位

面向小学、初中学生的交互式学习产品。目标不是回答问题，而是**教会学生解一类题目、学会一个知识点**，并在数月到数年的尺度上持续跟踪其成长。

产品有两种并列的一等模式：

- **Chat（自学）**：学生驱动。带着自己的题目或疑问来，问什么答什么，范围无界。
- **Chalkboard（上课）**：系统驱动。有预设教学目标、有顺序、有检查点，范围有界。

类比：Chat 相当于自己看书做题，Chalkboard 相当于去上一堂课。两者互为入口，**共用同一套视觉展示能力**，共享同一份学习记录。

**第一步只做数学。** 架构上不排斥其他学科（物理、化学、语文、英语等），但第一版不为多学科做设计投入。

## 2. 术语

| 术语 | 定义 |
|---|---|
| **知识点（KC）** | 最小的可教学单元，如"三角形中位线定理" |
| **题型（PT）** | 一类可识别、有共同解法的题目，如"倍长中线构造全等" |
| **误区** | 一个命名的典型错误模式，如"把中位线当成中线" |
| **Beat** | Chalkboard 讲解的原子节拍，含旁白、画面动作、可选检查点 |
| **Checkpoint** | Beat 上的一个提问点，学生在此作答，答错转入讨论室 |
| **课件** | 一个题型或概念对应的完整 Beat 序列，可跨学生复用 |
| **讨论室** | 课堂右侧的随行多角色对话区 |
| **单页 chalkboard** | 即兴生成的独立展示单元，有 id、可留存、可回看 |
| **画像** | 对一个学生的自然语言描述，以 wiki 形式维护 |
| **证据** | 一次结构化的学习记录，可用于计算 |

## 3. Chat（自学）

### 3.1 提问入口

- 拍照上传题目
- 文字输入题目
- 直接提问概念（"什么是相似三角形"）
- 上传作业/试卷（多题批量）

### 3.2 讲解

- 对单题给出讲解，必须包含**思路来源**：为什么会想到这一步，而不是只给出正确步骤
- 可使用全部视觉展示能力，包括生成单页 chalkboard（6.4）
- 讲解形态由内容需要决定

### 3.3 题型识别与归类

- 每一道进入系统的题，自动识别所属**题型**和**知识点**，挂载到课程图上
- 识别失败时降级到只挂知识点
- 归类结果对学生可见、可纠正

### 3.4 提示阶梯

学生表示"不会"时，不直接给答案，按四级递进：

1. **定向**：指出该关注题目的哪个条件
2. **唤起**：提示相关的知识点或已学题型
3. **局部示范**：演示关键一步，剩余留给学生
4. **完整示范** + 立即给一道同题型变式题

用到第 3、4 级才做对的题，不计入正向掌握证据。

### 3.5 上课建议

讲解结束后，模型可以建议进入 Chalkboard：

> "这道题属于『倍长中线』，这类题还有 3 个常见变式。要不要上一节课把这类题吃透？"

**是否上课由学生决定。** 系统只建议，不强制路由。

建议的触发条件（示例，需细化）：
- 该题型学生此前错过多次
- 该题型有成套变式，单题讲解无法覆盖
- 暴露出先修知识点缺口

Chat 与 Chalkboard 的区别不在视觉能力（两者相同），而在**系统性**：Chalkboard 有教学顺序、有检查点、有变式覆盖、有"确认你真的会了"。

## 4. Chalkboard（上课）

### 4.1 课的形制

一节课对应一个明确的教学目标，分两种：

| 课形 | 目标 | 验收方式 |
|---|---|---|
| **题型课** | 吃透一类题 | 若干道同题型变式题的正确率 |
| **概念课** | 理解一个概念 | 概念辨析题 + 用自己的话解释 |

单节课时长：初中 15–25 分钟，小学 10–15 分钟。

### 4.2 课的结构

一节课是一个**线性 Beat 序列**。每个 Beat 包含：

- **意图**：引入 / 唤起先修 / 动机 / 步骤 / 关键洞察 / 易错提醒 / 小结
- **旁白**：讲什么
- **画面动作**：展示什么、如何变化
- **检查点**（可选）：让学生回答什么

「动机」类 Beat 在任何非平凡步骤之前是必需的——必须先说明"为什么会想到这么做"，再执行这一步。

**主时间线不分叉。** 课件一次性生成，所有学生的主线内容相同。因人而异的部分发生在讨论室里（4.4）。

### 4.3 Checkpoint

一节课设 3–5 个 checkpoint，形态就是"停下来，问一句，等回答"——接近真实课堂里老师提问的样子。

| 作答结果 | 处理 |
|---|---|
| 答对 | 一句肯定，继续主线 |
| 答错 | **转入讨论室**处理，讲完回到原位置继续 |
| 表示不会 | 转入讨论室，从更小的子问题开始 |
| 暴露先修缺口 | 提示可中止本课转先修课，由学生决定 |

设计要点：

- **不预制补救支线。** 处理错误的能力在讨论室里，不需要为每个误区另写一份内容。课件预制成本因此保持 1 倍。
- **checkpoint 是唯一的学习信号来源。** 「看完了」不等于「学会了」；没有 checkpoint，一节课结束无法判断是否有效。
- **checkpoint 是系统主动的。** 讨论室解决"学生想问"，checkpoint 解决"系统要查"——真正跟不上的学生往往不会主动提问，必须被拦一下。

### 4.4 讨论室

课堂右侧常驻一个多角色对话区，学生可随时插话。这是课堂里所有非线性交互的统一出口。

进入方式：

- 学生主动插话
- checkpoint 答错或表示不会（4.3）
- 课件中预设的讨论点（角色主动发起）

讨论室内的能力：

- 多角色参与（4.5）
- **生成单页 chalkboard 即兴讲解**（6.4），不影响主时间线上已生成的内容
- 使用提示阶梯（3.4），不直接给答案

讨论结束后回到主时间线原位置继续。

**偏离当前教学目标的提问**：可选择存入「课后问」队列，不打断节奏，下课后在 Chat 中处理。

### 4.5 多角色

课堂内有多个 AI 角色，每个角色必须承担明确教学功能：

| 角色 | 功能 |
|---|---|
| **主讲** | 推进教学主线、提出 checkpoint |
| **同伴** | 提出学生不敢问的问题；**故意给出典型错解，由学生纠正** |
| **助教**（可选） | 换一种表征方式重讲 |

同伴犯错让学生纠正是核心机制之一：学生从被教者转为教者，同时规避了 AI 直接泄露答案。

### 4.6 课件复用与个性化

课件按**题型/概念**为单位预制，跨学生复用。

个性化发生在**装配层**和**讨论室**，不在课件生成层：

- 装配层：根据画像决定启用哪些 checkpoint（已掌握的先修不必再查）、起点、详略
- 讨论室：即兴应对这个学生的具体问题和错误

同一份课件对不同学生表现不同，但不需要为每个学生重新生成内容。

### 4.7 课程来源

- **系统建议**：基于画像给出"今天建议上这节课"以及理由（"你这类题最近错了 3 次"）
- **从 Chat 升级**：见 3.5
- **从错题本发起**：见 7.1
- **学生自选**：按教材章节或题型浏览

系统建议来源：薄弱题型、先修缺口、到期复习。

## 5. 课后

### 5.1 验证题

每节课结束必须有 1–3 道验证题。这是判断"这节课有没有效"的唯一依据。

### 5.2 变式练习

题型课结束后提供变式题，沿该题型的**变式维度**变化（数字、图形位置、条件顺序、所求量、表征形式）。

判定标准：能跨越至少一个变式维度做对，才算掌握该题型；只做对原型题不算。

### 5.3 间隔复习

- 系统按遗忘规律安排复习时间点
- 出错过的内容优先进入复习队列
- 复习以「一道题」或「一个小检查」的形式出现，不重复整节课

## 6. 支撑能力

### 6.1 知识库

| 类别 | 内容 | 作用 |
|---|---|---|
| **课程图** | 知识点、题型、先修关系、课标映射 | 全系统的坐标系。所有题目、素材、学习记录都挂在它上面 |
| **题库** | 题目、答案、解析、难度、来源 | 供出题、变式、复习使用。含学生带来的题 |
| **素材库** | 教材、讲义等原文 | 讲解时的依据来源 |

课程图是另外两者的前提。

### 6.2 画像（LLM Wiki）

学生画像以**自然语言 wiki** 的形式维护，是 AI 理解这个学生的主要入口。

内容分区（示例）：

- **基本情况**：学段、教材版本、目标
- **兴趣与偏好**：怎么称呼、兴趣爱好（用于举例）、语速、表达偏好
- **认知特点**：怎么想问题、习惯性的思维方式、卡点规律
- **学习状况**：各知识点/题型的掌握情况叙述、反复出现的误区

特性：

- 学生和家长**可读、可编辑**
- 由 AI 在学习过程中持续更新
- 每条陈述带来源引用（哪次学习产生的判断），可追溯

初始化：不做入学诊断。第一版由学生自行填写少量信息（年级、教材版本、自认为薄弱的地方、兴趣爱好等）建立初版 wiki，之后靠学习过程逐步修正。

### 6.3 学习证据

与画像并列的另一条数据线，**结构化、只追加、不修改**：

- 哪道题、属于哪个题型、对错、错在哪一步、命中哪个误区、用了几级提示、耗时
- checkpoint 作答结果、是否转入讨论室
- **学生在可交互展示内容里的操作**（见 6.5）
- 判定来源（确定性检查 / AI 判定 / 人工）和置信度

| | 形态 | 用途 |
|---|---|---|
| **证据** | 结构化记录 | 可计算：复习队列、错题本按题型聚合、"这类题错了 5 次" |
| **画像** | 自然语言 wiki | 可表达：注入 AI 上下文、给学生和家长看 |

约束：**画像必须能从证据重新生成**。否则 wiki 一旦漂移或自相矛盾，没有修复手段。

### 6.4 单页 chalkboard

即兴生成的独立展示单元，两种模式共用：Chat 里回答"这条辅助线怎么画"，讨论室里承担即兴讲解。

它必须是**有 id 的持久单元**，不是易失的覆盖层：

- 默认留存在本次学习记录中，学生课后可回看
- 可被后续引用：进错题本、被复习引用、作为学习证据的一部分
- 学生可显式收藏或丢弃

对比：OpenMAIC 讨论中的白板是当前场景上的覆盖层，`wb_clear` / `wb_close` 之后即消失，不进 `stage.scenes`，无独立 id，事后无法回看。我们要的是同样即兴、但产物持久。

### 6.5 展示内容的可交互性

展示内容中的可操作部分（拖动点、作辅助线、调参数、改数值等），学生的操作必须**回传给 AI**，不能只在展示内部自娱自乐。

要求：

- 操作成为 AI 的**观察输入**：AI 知道学生此刻做了什么，可以就地回应（"你把辅助线连到了 AC 上，想想为什么这样连不通"）
- 操作成为**学习证据**（6.3）：写入记录，可用于判定和复习
- checkpoint 因此可以要求动手，而不只是选择题和填空（"把这条辅助线画出来"）

不做这一层，交互就退化为"学生自己玩，AI 不知道"。

## 7. 长期跟踪的可见出口

长期跟踪必须有界面呈现，否则对用户等于不存在。

### 7.1 错题本

- 自动收集，**自动按题型聚合**，不要求学生手动整理分类
- 每个题型下显示：错过几次、常犯哪个误区、是否已掌握
- 可回看当时的讲解和单页 chalkboard
- 可以从错题本直接发起对应的 Chalkboard 课程

### 7.2 学情报告

- 面向学生：掌握了什么、卡在哪、下一步学什么
- 面向家长：进度、投入时间、变化趋势
- 必须能回答「为什么系统认为我没掌握这个」

### 7.3 画像页

学生可以直接查看和编辑自己的画像 wiki（见 6.2）。

## 8. 待定

1. **学段范围**：小学和初中在识字量、注意力、付费决策上差异很大
2. **题型库覆盖策略**：只覆盖高频核心题型（识别准但范围外的题多），还是尽量全覆盖（成本高且识别率下降）
3. **概念课的验收标准**：题型课的验收是硬的（变式题对错），概念课容易做成自我感觉良好
4. **未知误区的沉淀**：讨论室即兴处理过的错误，是否要反馈成课程图上的新误区条目
5. **分期顺序**：哪些功能进第一版
