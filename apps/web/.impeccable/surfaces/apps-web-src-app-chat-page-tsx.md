## Scope and Mode

`/chat` is the desktop student learning workspace. It is an Operate surface for repeated use, not onboarding, marketing, or a course dashboard.

## Audience and Job

A student arrives with a math problem or a point of confusion. They need to recognize the active conversation, read a patient explanation at a stable line length, ask the next question, and understand when the tutor is using a tool or waiting for approval.

## Content and Primary Task

The first view shows one realistic geometry conversation already in progress. The primary task is continuing the conversation from the anchored composer. Conversation search, starting a new conversation, attaching work, choosing a model, stopping a response, approving a tool action, and recovering from failure must be operable demo states.

## Chosen Direction

Warm Learning Desk extends Creatorflow main's Warm Editorial Operations into a three-region learning surface. A 248px conversation rail and 296px learning-context rail frame an unboxed central transcript. The memorable moment is the tutor's explanation sitting beside a compact, inspectable record of the exact problem, knowledge points, and agent work that produced it.

## Constraints

Desktop only for this phase. Use warm canvas, paper, charcoal actions, and rare clay emphasis. No invented primary color, gradients, glass, decorative classroom imagery, fabricated mastery scores, nested cards, or generic assistant bubbles. The demo must label simulated behavior honestly and preserve accessible names, keyboard focus, and non-color status cues.

## Unresolved Decisions

Agent Runtime API contracts, persisted attachment handling, rendered math/Markdown libraries, and the full Chalkboard transition remain integration decisions after the interactive shell is validated.
